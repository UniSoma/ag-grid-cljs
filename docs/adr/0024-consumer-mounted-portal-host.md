# 0024. Portal tier: consumer-mounted portal-host + portal-renderer, beside per-cell roots

- Status: accepted, 2026-08-12
- Origin: knot ticket agd-01kzva6hgxq5, opened on a field-consumer submission (Agilis webapp, Mantine 9.4.1) reporting silent empty cells from provider-based `react-renderer` content (tickets are ephemeral; this record is self-contained)

`react/portal-renderer` + `react/portal-host` ship as a fourth renderer tier **beside** `react/react-renderer`, not replacing it. The CONSUMER mounts the host once, anywhere under their providers; portal cells `createPortal` into AG Grid's cell DOM from that host, so providers, theme, locale, stores **and error boundaries** flow into cell content natively — error boundaries being the thing no value-bridge can ever deliver into a separate root. This opens and answers the question ADR 0023 explicitly severed ("making context flow is a separate, consumer-facing API question this ADR deliberately does not open"): legitimately open, because 0023's kill rule never measured context inheritance, and the portal design it rejected was a *library-created* host root, not this one.

## Context

ADR 0011 positions `react-renderer` as right for sparse interactive columns in React-hosted apps. In practice those columns are design-system components, and every mainstream design system is provider-based; React context does not cross roots, so a per-cell root amputates exactly the composition mechanism such components rely on. The field consumer's first migrated grid with Mantine cell content threw `MantineProvider was not found` in every rendered cell and painted empty spans — compiling clean, linting clean, silent in a production console. Ticket agd-01kzva5kq1j5 shipped the consumer's-half answer: the provider-wrap recipe in `docs/framework-composition.md`, the dev `onUncaughtError` diagnostic with the provider-shaped hint, and a raw-createContext browser test pinning the detachment. The wrap's cost is real and documented — each visible cell mounts its own provider (cells *manage* what they should only *consume*), and no wrap can deliver error boundaries.

The grilling session over the submission decided the spike proceeds on **architectural grounds**: elegance is the criterion, measurement is telemetry, not gate. The kill rule was three correctness gates — *(a)* no DEV error class, *(b)* no empty-cell paint, *(c)* provider-based cell content renders under the consumer's own providers AND error boundaries with zero consumer-side bridging — gate (c) being the criterion 0023 excluded.

The spike harness (browser suite: a real React FC whose `useEffect`s create the grid, force-refresh cells, and push rows; 8 portal cells; headless Chromium; React 19.2.7 DEV; ag-grid-community 36.1.0) measured all three:

| kill-rule gate | result |
|---|---|
| (a) DEV errors: `create-grid!`, `refreshCells {:force true}`, `set-rows!`, each from a `useEffect` | 0 console errors across all legs |
| (b) empty-cell paint (per-frame monitor: portal-column cell present with no text) | `{:create 1, :refresh 0, :set-rows 1}` — identical to ADR 0023's measured baseline for every tier; the residual frame is AG Grid's own async cell build (the cell div exists a frame before any renderer's gui attaches) |
| (c) context + boundaries, zero bridging | a bare portal cell reads the app-level `createContext` value; a throwing portal cell is caught by the consumer's own error boundary (fallback renders); cells registered before the host mounts drain into a late host under *its* providers |

Gate (c) is the new capability; gates (a) and (b) show the portal gives it up nothing the batched flush won.

## Decision

1. **Beside, not replacing.** Both React tiers are public: `react-renderer` (self-contained, context-free content) and `portal-renderer` + `portal-host` (provider-based content). The per-cell tier is untouched — its scheduling, teardown corrections, and docs all stand. Declared intent: the per-cell tier may retire in a later **major** only after the portal tier has production hours; nothing retires now. Auto-switching `react-renderer` cells to the portal when a host is present was ruled out hard — a silent architecture change is a new silent failure mode, the exact class this tier exists to kill.
2. **Host discovery is a module-level registry**, the precedent being this namespace's own render queue ("one flush covers every cell of every grid on the page", ADR 0023). The host registers itself on mount and portal cells look it up, so no live object ref enters the options map (ADR 0021) and `portal-renderer` stays a deferred, rebuild-stable value — the render fn is the payload, same ownership shape as `:react-renderer`. The oldest mounted host is active; a second concurrent host dev-warns (`::second-portal-host`, once per process — a statement about what the consumer wrote, ADR 0022) and renders nothing, taking over only if the first unmounts.
3. **Missing host: cells queue; never a per-cell-root fallback.** Registrations made with no host mounted wait in the registry and the cell paints empty; when a host mounts, the queue drains through it. If cells are still hostless one macrotask after the first registration, dev builds warn ("portal cells waiting — mount ag-grid-cljs.react/portal-host under your app's providers"). Its period is once per **hostless episode**: cells-waiting-with-no-host is a relationship between live things (ADR 0022), so the module owns a latch that is set when the episode warns and cleared when a host mounts — churn within one hostless episode stays one warning, and a fresh episode after a host unmounts warns again rather than going silent. One macrotask tolerates any mount order within a tick — a consumer whose effects create the grid before the host commits never sees the warning.
4. **The scheduling machinery moves into the host rather than dying — recorded honestly.** Host commits must land before paint (0023: a portal host escapes a React commit the same way the batched flush does — a microtask — or not at all), so cell registrations, refreshes, and removals drain through the SAME one-`flushSync`-per-microtask queue the per-cell tier uses. The render contract is therefore identical to ADR 0023's: content lands before paint, not on the call stack. What dies: the per-cell `createRoot`/`unmount` lifecycle, the deferred-unmount correction and its cleanup-ordering trade-off, the destroyed-guard race (a registry change between queue and drain is just the state the host renders next), and the React #26281 per-cell unmount audit — not shrunk to one library root but gone from the library entirely, since the only root in play is the consumer's own app root. `refresh` updates the same portal in place, so React component local state survives value refreshes, as in the per-cell tier.
5. **This ADR records the whole context-flow answer.** The provider wrap (agd-01kzva5kq1j5) remains the per-cell tier's supported pattern and the uncaught-cell-error diagnostic remains its safety net; the portal tier is the zero-bridging answer for provider-based content, and the docs present them as that pair. Docs use the existing tier numbering — the portal is Tier 4 in `docs/cell-rendering.md`, not a "4b".

## Consequences

- Provider-based cell content needs exactly one sentence of consumer API: *render `portal-host` once under your providers.* Theme, locale, stores, and error boundaries then reach every portal cell with zero bridging; the Mantine wrap shape and the hand-rolled context bridge both become unnecessary on this tier.
- A consumer error boundary around the host catches throwing cells — and its granularity is the consumer's: one boundary around the host fields every cell's errors together; per-cell isolation means boundaries inside the cell content. React 19 DEV still logs boundary-caught errors via its default `onCaughtError`; that log is React's, not a library warning.
- Misconfiguration (portal cells, no host) paints empty cells with a dev warning after a macrotask. In a production build the cells are empty with no console output — same silence class as the per-cell provider failure, which is why the dev warning exists and why there is deliberately no fallback that would paper over it with a *detached* render.
- Host unmount unmounts all portal cell content with it (they are children of its tree); the registry keeps the cells, so a replacement host picks them up. Grid destroy unregisters its cells regardless of host state.
- Measurement rode along as telemetry only, per the spike decision — no performance gate was set. What was actually collected: the per-leg empty-frame counts, which the harness logs on every suite run. Scroll-churn and provider-cost numbers were named as candidate telemetry and NOT collected in this spike; they remain for the production-hours evidence the retirement question needs. ADR 0011's ~100–300 root create/destroy per second scroll caveat does not apply to portal cells (no roots), but virtualization churn now re-commits the host once per drained batch instead.
- `CONTEXT.md`: the *Renderer tiers* entry becomes four levels and a *Portal host* term is added. ADR 0011 gains a correction note on its "three tiers" commitment; ADR 0023 gains a pointer note on its severed-question line.
- The browser suite gains `react_portal_test.cljs` — the spike harness committed as the regression guard (ADR 0015), covering all three kill-rule gates and both dev warnings.

## Considered options

- **Library-created host root (one per grid)** — rejected by ADR 0023 for reasons this design dissolves rather than relitigates: a library-owned root inherits an empty library-owned tree, so context transparency was a strawman there; a consumer-mounted component inherits the consumer's tree by construction, which is the entire point.
- **Auto-switch on host presence** (`react-renderer` cells render through the host when one is mounted) — rejected hard: mounting an unrelated host would silently change every existing cell's context story and failure modes; silent architecture change is a new silent failure mode.
- **Per-cell-root fallback when no host is mounted** — rejected: the fallback renders *detached*, so provider-based content would throw and paint empty exactly as before — the failure class this tier exists to close, reintroduced as a race on mount order. Queue and warn instead.
- **Replace `react-renderer` now** — rejected: the per-cell tier has production hours and a measured contract; the portal has a spike. Beside now, retirement at earliest in a later major, only with production evidence.
- **A `:wrap` option on `react-renderer`** (the submission's step 1) — not taken as API: agd-01kzva5kq1j5 shipped the wrap as a documented consumer pattern instead. An option would bless a shape that still cannot deliver error boundaries and still makes cells manage providers; the portal is the structural answer.
- **Host as a grid option (live component/element ref in the options map)** — rejected: ADR 0021 keeps live object refs out of the options map; a registry keeps the renderer value deferred and rebuild-stable, and one host serves every grid on the page.
